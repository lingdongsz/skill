# 用户接口（套餐信息 / 积分）

用于查询当前 API Token 绑定用户的套餐列表、积分额度、已消耗积分、有效期和套餐状态。

## 接口选择规则

`/user/package/usage` 只封装 1 个接口：

- `/user/package/usage`：当前用户的套餐列表 + 积分消耗情况（**不消耗积分**）。
  - **什么时候调用**：
    - 用户问"我还剩多少积分""我的套餐是什么""我的额度够不够""我的套餐什么时候到期"。
    - 准备连续调用大量接口前，帮用户确认积分是否够用（可选的贴心动作）。
    - 收到后端返回「积分不足 / 使用次数已满」错误时，调用此接口告诉用户具体情况。
  - **什么时候不调用**：
    - 纯业务分析、纯咨询类问题（不涉及用户套餐/积分）。
    - 每次调用其他 API 前都查一遍（没必要，反而增加请求），建议按需查询。

## `/user/package/usage` 我的套餐信息

> ⚡ **积分消耗**：**0 积分**（查询自身套餐信息不扣费）

返回当前用户名下所有有效/过期/已用完的套餐列表，按购买时间倒序排列。

### 请求参数

无。通过请求头中的 `Authorization: Bearer <Token>` 自动识别所属用户。

### 返回字段（按接口返回顺序）

> **【最新结构说明】** 外层返回公共字段 + `data` 对象（包含用户信息 `nickName` / `phoneNo` 和套餐数组 `packageList`），每条套餐字段见下方 `packageList[*]`。

#### 外层公共字段

- `code`：状态码，`0` 表示成功，非 0 表示失败
- `msg`：状态信息，成功为 `"success"`
- `data`：响应主体（对象），见下一节
- `timestamp`：服务端时间戳（毫秒）

#### `data` 对象字段

- `nickName`：**用户名 / 昵称**（本次新增），如 `"大猫"`
- `phoneNo`：**电话号码**（本次新增），如 `"13926539075"`
- `packageList`：套餐数组，每一条为一份用户套餐（字段见下一节）

#### `data.packageList[*]` 单个套餐字段

- `settingId`：用户配置 ID（内部主键，一般不展示）
- `tcId`：套餐编码（String / Integer），对照表见下方「套餐类型映射」
- `tcCount`：套餐**总积分额度**（无论是否是「无限制」套餐，都直接显示数据库里的 tc_count 数值，不会返回 null）
- `useCount`：套餐**已消耗积分**（未使用为 0，不会返回 null）
- `buyDate`：购买时间，ISO 格式（如 `2026-07-01T10:00:00`）
- `deadLine`：过期时间，ISO 格式（如 `2026-10-01T23:59:59`）

> **衍生字段提示**：前端/脚本如需展示「剩余积分」「套餐中文名」「状态」「有效期描述」，请根据下面的映射规则和公式自行计算：
> - `remainingPoints = tcCount - useCount`
> - `tcName`（套餐中文名称）：依据 `tcId` 查下方映射表
> - `packageTypeDesc`（套餐类型描述）：依据 `tcId` 查下方映射表
> - `status`（套餐状态）：
>   - **有效**：在有效期内 且（无限制 或 剩余积分 > 0）
>   - **已过期**：当前时间超过 deadLine
>   - **已用完**：在有效期内 但 剩余积分 ≤ 0
> - `validPeriod`（有效期描述）：
>   - 正常套餐：`yyyy-MM-dd ~ yyyy-MM-dd`（如 `2026-07-01 ~ 2026-10-01`）
>   - 无限制套餐（`tcId=99`）：`长期有效`
>   - 日期缺失时返回空字符串 `""`

#### 套餐类型映射（tcId → 含义）

| tcId（整数/字符串） | 套餐中文名称 tcName | 套餐类型描述 packageTypeDesc | 说明 |
| -----------------: | :-------------- | :---------------------- | :-- |
| 1 | 一个月 | 月度套餐 | 常规套餐，有效期 30 天（自购买日起） |
| 2 | 一季度 | 季度套餐 | 常规套餐，有效期 90 天 |
| 3 | 半年 | 半年套餐 | 常规套餐，有效期 180 天 |
| 4 | 一年 | 年度套餐 | 常规套餐，有效期 365 天 |
| 11 | 一次性加餐包 | 加餐包（可叠加） | 不设独立有效期，跟随主套餐或设置较长截止时间，可多份叠加 |
| 99 | 无限制 | 不限量套餐 | 积分额度极高/内部不限量，tcCount 仍按数据库原值显示（通常为超大数字），不会为 null |
| 其他/未知 | 未知套餐 | 未知类型 | 兜底展示 |

> 上面示例中各套餐的**衍生字段**（前端/脚本自行计算）：
> - `tcId=99` → 套餐名「无限制 / 不限量套餐」，剩余积分 `= 200000000 − 132 = 199999868`，状态「有效」，有效期「长期有效」
> - `tcId=2` → 套餐名「一季度 / 季度套餐」，剩余积分 `= 5000 − 1280 = 3720`，状态「有效」，有效期 `2026-07-01 ~ 2026-10-01`
> - `tcId=11` → 套餐名「一次性加餐包 / 加餐包（可叠加）」，剩余积分 `= 1000 − 300 = 700`，状态「有效」，有效期 `2026-08-01 ~ 2027-08-01`
> - `tcId=1` → 套餐名「一个月 / 月度套餐」，剩余积分 `= 1000 − 1000 = 0`，当前时间超过 deadLine，状态「已过期」

## 使用提示

- **用户信息展示**：请首先展示 `data.nickName` 和 `data.phoneNo`（如「用户：大猫（手机号：13926539075）」），再展示套餐信息，方便用户确认身份。
- 一个用户可以同时拥有多份套餐（主套餐 + 多份加餐包 + 无限制），套餐都放在 `data.packageList` 数组里，建议前端列表展示。
- 判断「积分够不够」时，取所有「有效」的套餐，将它们的 `tcCount − useCount`（剩余积分）相加，再和本次需要消耗的积分比较即可。
- 如果所有有效套餐剩余积分都接近或用完，建议提示用户续费或购买加餐包。
- `tcId=99`「无限制」套餐虽然 `tcCount` 是超大数字（如 200000000），但前端显示时可以根据套餐名单独处理为「∞」或「不限量」，不要被数字误导。
