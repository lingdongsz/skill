# 类目接口

用于查询 Mercado Libre 站点的全量类目树，为后续的行业趋势分析、商品搜索、价格分布、
店铺筛选等接口提供 `--category-id` 参数。

【⚠️ 极其重要：后端接口参数与脚本本地能力的边界】

- 真实后端接口 `GET /category/tree` **只接受 1 个请求参数：`siteId`（站点）**。
  **绝对没有** `depth`、`keyword`、`search`、`page`、`pageSize` 之类参数，
  任何情况下都**不要**把这些值拼到 URL 或 body 里传给后端，否则请求会报错。
- 本文档以及 `category_tree.py` 里提到的「关键词搜索」「按深度截断显示」
  「JSON 导出」「缓存刷新」等等，全部是 **Python 脚本拿到完整类目树之后的本地后处理能力**，
  不会再发起额外 HTTP 请求，也不会多扣积分。

## 接口选择规则

`category_tree.py` 封装 1 个后端接口（+ 一套本地后处理）：

- `/category/tree`：站点全量类目树（递归结构，返回每个节点的 `id / name / zhName / children`）。
  - **什么时候调用（即真正请求后端）**：
    - 首次查询某站点（本地还没有缓存文件）。
    - 加了 `--refresh` 强制刷新（后端类目确实有更新时）。
  - **什么时候只走本地缓存、不请求后端、不花积分**：
    - 该站点已经有缓存文件、且未过期、也没加 `--refresh`。
    - 此时即使用了 `--search 手机壳` / `--depth 5` / `--output json`，
      也只是在本地 JSON 上做过滤/打印/导出，**完全不调用后端**。
  - **什么时候不调用脚本、直接跳过**：
    - 用户已经明确给出了类目 ID（如 `MLM458037`），直接拿去给 `trends.py` / `search_items.py` 即可。
    - 只要商品列表、只要店铺数据，不需要按类目过滤。

> ⚠️ **积分消耗提醒（方案 C 本地缓存）**：脚本内置了按站点缓存。
>
> - **首次调用**某站点（无本地缓存）：真实请求 `/category/tree?siteId=XXX`，消耗 **10 积分**，并把结果写入 `skills/ljxp-skills/cache/category_tree_<站点>.json`。
> - **后续同站点查询**（缓存存在、未过期、未加 `--refresh`）：直接读本地文件，**不调用后端接口、不消耗积分**。缓存命中时甚至可以省略 `--token`。
> - 默认缓存有效期 7\*\* 天\*\*（可用 `--cache-ttl` 调整，`--cache-ttl 0` 表示永不过期）。加 `--refresh` 可强制重新拉取并覆盖缓存（本次消耗 10 积分）。
> - 建议：首次查一个站点时顺便跑通，之后所有关键词搜索、深度浏览都用缓存免费搞定；`--refresh` 只在后端类目确实更新过的时候再用。

## `/category/tree` 站点类目树

> ⚡ **积分消耗**：请求后端接口消耗 **10 积分**；脚本命中本地缓存时不请求后端、**免费**（详见上方缓存提醒）

返回指定站点的完整多级类目树（根节点为顶级类目，逐级嵌套）。

### 请求参数（后端只接这一个，其他参数一律不要传）

| 参数       | 类型     | 必填 | 说明                                                              |
| :------- | :----- | :- | :-------------------------------------------------------------- |
| `siteId` | String | ✅  | 站点 ID，可选值：`MLM`（墨西哥）、`MLB`（巴西）、`MLC`（智利）、`MLA`（阿根廷）、`MCO`（哥伦比亚） |

### 脚本本地后处理参数（不发给后端、不额外花积分）

以下参数只影响 Python 脚本「如何展示和使用已拿到的完整树」，不会出现在 HTTP 请求里：

| 参数               | 说明                                                          |
| :--------------- | :---------------------------------------------------------- |
| `--search "关键词"` | 【本地过滤】在已缓存的完整树上做关键词匹配（`zhName`/`name`/`id`），只保留命中节点及其完整祖先链。 |
| `--depth N`      | 【本地打印截断】默认 `3`，只打印前 N 层；`0` 表示不限。                           |
| `--output json`  | 【本地输出】以 JSON 格式输出完整（或过滤后）的树结构，方便交给 AI 或其他工具。                |
| `--refresh`      | 【本地缓存控制】忽略本地缓存，重新请求后端拉取一份并覆盖旧缓存文件（本次 10 积分）。                |
| `--cache-ttl 秒数` | 【本地缓存控制】缓存有效期，默认 604800=7 天，`0` 表示永不过期。                    |
| `--token`        | 【鉴权参数】只有在**真实请求后端**（首次或 `--refresh`）时才需要；命中缓存可省略。           |

### 返回字段 CategoryData

每个节点字段一致，`children` 递归嵌套；叶子节点的 `children` 为 `null` 或空数组 `[]`。

| 字段         | 类型                  | 说明                                                                                     |
| :--------- | :------------------ | :------------------------------------------------------------------------------------- |
| `id`       | String              | 类目 ID，格式为 `站点前缀 + 数字`，如 `MLM458037`、`MLB1051`。**这是传给下游接口的** **`--category-id`** **值**。 |
| `name`     | String              | 类目英文名称（平台原生名称，如 `Cell Phones & Accessories`）。                                          |
| `zhName`   | String              | 类目中文名称（本地化翻译，匹配用户中文关键词）。                                                               |
| `children` | List\<CategoryData> | 子类目列表，递归嵌套，结构完全相同。叶子节点为 `null` 或 `[]`。                                                 |

## 使用提示

1. **类目树可能很大**（有的站点有几千节点），直接打印整棵树在 Markdown 里放不下。
   建议脚本里默认 `--depth 3`，只有用户明确说要看完整结构时才 `--depth 0` 不限深度。
2. **定位具体类目优先用关键词过滤**（`--search`）：
   - 例如用户说「想做手机壳」，直接 `--search 手机壳` 或 `--search case`，
     结果会只显示匹配节点及其完整祖先链（父路径、祖父路径一直到根），方便确认类目层级。
   - 关键词同时匹配 `name`（英文）、`zhName`（中文）、`id`（类目ID），对用户输入不需要做翻译。
   - 关键词过滤是**在本地缓存里做的**，不需要再调后端接口、不需要额外花积分。
3. **拿到目标** **`id`** **后，就可以喂给下游接口了**：
   - 行业趋势：`trends.py --type statistical --category-id <ID>`
   - 价格分布：`trends.py --type price_list --category-id <ID>`
   - 商品搜索：`search_items.py --category-id <ID>`
   - 竞争店铺/商品/品牌：`trends.py --type top_sellers / top_items / top_brands --category-id <ID>`
4. **同一个站点，第一次查花 10 积分写入缓存，之后所有查询都免费**。不管查多少个关键词、看多少层深度，都不会再请求后端接口。
   - 缓存文件位置：`skills/ljxp-skills/cache/category_tree_<站点>.json`（可手动删除，删除后下次会重新花 10 积分拉取）。
   - 要查看缓存写入时间：命令运行后 stderr 里会打印「本地缓存（写入于 YYYY-MM-DD HH:MM:SS）」。
   - 缓存 7 天后自动失效。想强制更新（后端加了新类目时用）：加 `--refresh` 参数，同时需要提供 `--token`。
5. **跨站点对比**：不同站点（MLM vs MLB 等）的类目 ID 和层级不同，**类目 ID 不能跨站复用**。
   如果用户要做多个站点对比，每个站点都要**单独**有第一次付费缓存（之后该站点内查询免费）。
6. **`--token`** **不是每次都要给**：命中本地缓存时，脚本不需要调接口，可以完全省略 `--token` 和 `LJXP_TOKEN` 环境变量。只有首次拉取或 `--refresh` 时才必须提供 Token。
